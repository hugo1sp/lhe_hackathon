# Migrai – migraine forecast from wearable data

**Live demo: https://hugo1sp.github.io/lhe_hackathon/**

Migrai forecasts the likelihood of a migraine 1, 2 and 3 days ahead from smartwatch data (sleep, resting heart rate, HRV, activity, stress). The user sees a probability, not just a yes/no.

Collecting good data is the main bottleneck for existing solutions, so data collection is our focus: instead of a daily diary, the app asks at most one one-tap question per day, and only when the answer is informative.

## How it works

1. **Simulator** (`simulator/simulate.py`) – generates synthetic wearable + migraine data per person and day, with person-specific triggers, a 1–2 day prodrome before some attacks (frequency and strength vary per person), unobserved causes so attacks are only partly predictable, non-wear days and unreported attacks. Calibrated against two public datasets (mBrain21 and the hebaqueen wearable migraine dataset, see `datasets/stats.py`).
2. **Question policy** (`collection/questions.py`) – picks at most one question per day:
   - `attack_check` – activity crashed vs. personal baseline: confirm or rule out an attack
   - `prodrome` – forecast risk is high: capture early warning signs
   - `anomaly` – a signal is off: ask why (stress, illness, alcohol) to separate confounders
   - `no_data` – watch recorded nothing: the answer is the only data that day
   - `checkin` – nothing asked for a few days: secure a confirmed "no migraine" day

   `collection/simulate_answers.py` simulates users answering, and every tap becomes a model-ready label (`data/labels.csv`).
3. **Base model** (`model/base.py`) – one shared LightGBM per horizon (1, 2, 3 days ahead) for all users that forecasts a migraine using only what every user has without answering anything: smartwatch signals, deviation from the person's own 28-day baseline, sleep regularity, non-wear and the target day's weekday. Cycle day, sex, age and migraine history are left to the per-user personal layer, which builds on the base probability (`data/base_oof.csv`). LightGBM was chosen after comparing 9 model families. Evaluated with 5-fold CV grouped by person, scored against ground-truth attacks on every day (including unanswered ones).

## Run

```bash
./run.sh
```

Creates `.venv`, installs `requirements.txt` and runs the whole pipeline: simulate data → simulate answers → export site data (`docs/data.json`) → train the base models (`data/model_base_d{1,2,3}.txt`). Every push to `main` runs the same pipeline on GitHub Actions and redeploys the live demo.

`datasets/stats.py` (recomputes calibration stats from Kaggle) is not part of `run.sh`.

## Layout

- `simulator/` – synthetic wearable + migraine data
- `datasets/stats.py` – calibration statistics from public datasets
- `collection/` – question policy and simulated answers
- `model/` – LightGBM forecast models
- `frontend/export.py` – exports data for the site
- `docs/` – the live site (GitHub Pages)
- `app/` – Migrai app prototype with example user Anna (simulated person P0187); open `app/index.html` in a browser. Data is baked by `app/build_data.py`.
- `demo/` – interactive "Follow Anna" walkthrough; open `demo/index.html`

All data is simulated. `data/` is generated by `run.sh` and gitignored.
